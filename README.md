# tty-echo-server
A simple server running in a Linux terminal (console). It allows you to enter and emulate commands, the tokens for which are provided in a special dictionary file.

Программанаписа на языке С/С++ под Linux. Компилируется со стандартом -std=c++17.
Программа-сервер запускается в терминале Linux. Он ожидает ввода тех или иных символов, например, команд, приведенных в файле-словаре vocabulary.txt. Если соответствующая команда есть в словаре, то сервер вернет "результат ее обработки". Если нет, выдаст сообщение, что такой команды нет. 
После ввода команды (последовательности символов) нужно нажать клавишу Enter либо Ctrl+D. Выход из программы (в обычный режим терминала) осуществляется, как обычно, через Ctrl+C.

Краткое описание. Для надежности, реализован перехват сигнала SIGINT (Ctrl+C). Сервер работает в цикле до тех пор, пока не получит этот сигнал (или пока не возникнет аварийная ситуация, критическая ошибка). 
После того, как команда введена и нажаты клавиши Enter либо Ctrl+D, сервер начинает считывать введенные символы по частям или порциями (а не за один прием). Это сделано с расчетом на будущее, если объемы команд будут достаточно большими. 
Функции расположены в том же самом файле, в целях компактности и удобства.
Основная проблема, которую пришлось решить при написании этой программы, заключается в том, что при чтении последовательности симвовов, введенных на терминале, по частям, у Linux, похоже, ОТСУТСТВУЕТ надежный способ узнать, закончились ли эти символы или нет. Вот если читать их сразу одним этапом - тогда все проще. Однако, при больших их объема это может вносить неудобства в работу компьютера. Поэтому сделано именно порционное чтение. 
Если пользователь нажимает клавишу Enter после ввода символов (команд), то все проще, т.к. это отслеживается по последнему символу, представляющему собой перенос строки (\n). А вот что касается Ctrl+D, здесь проблемнее. Ибо в каноническом режиме работы терминала Ctrl+D, похоже, ничего не выводит в терминал, вместо этого соответствующий байт напрямую передается ядру ОС. Нет и соответствующего сигнала, связанного с этой комбинацией клавиш (в отличие, например, от Ctrl+C). Поэтому пришлось применить просмотр очереди символов, попавших ядру (и незаблокированных), но пока еще не возвращенных серверу. Это сдеално при помощи функции ioctl(). 
Данное решение НЕ является надежным, ибо часть последовательности символов может быть заблокирована и временно недоступной ядру (например, в случае нештатных ситуаций или при замедлени работы компьютера). Однако это, видимо, нестрашно. Ибо если символы будут заблокированы, значит вводимая команда просто не дойдет до ядра и, следовательно, не будет выполнена, возникнет ошибка. Можно будет повторить эту команду снова.
